# Табличная библиотека для панели проектов (atlas)

Дата: 2026-10-08. Контекст: Tauri v2, фронтенд — vanilla JS без билд-степа и npm, CSP `script-src 'self'` → только файлы, закоммиченные в `static/vendor/`. Огрызок: `#ptbl` (8 колонок: бейджи источников, имя, зависимости, агенты, сессии, активность, путь, фокус), выбор через `atlas.selected` + `storage`, ширины через `atlas.colw.projects` (`<colgroup>` + `table-layout: fixed`), свежий баг класса: `<span>` в `<tr>` стал анонимной ячейкой и сломал fixed-layout. Размеры сняты с cdn.jsdelivr.net (`gzip -c`), даты релизов — с registry.npmjs.org, всё на 2026-10-08.

## Вердикт

Берём **Tabulator 6.6.1** (MIT, UMD-файл вендорится в `static/vendor/` без билда; js 454 КБ / 104 КБ gzip, css 28 КБ / 4 КБ). Это единственный зрелый вариант, где сворачиваемая группировка со счётчиками — штатная опция (`groupBy`/`groupHeader`), а не Enterprise-модуль или сторонний плагин; проект живой (6.6.1 от 2026-09-30). Заодно уходят `makeResizable`, colw-хендлеры и весь класс багов ручного fixed-layout — DOM строк строит библиотека, у нас остаются только formatter'ы и события. Стоимость: перебивка классов `.tabulator-*` под `--palette-*` (~60–100 строк CSS, у Tabulator в dist нет CSS-переменных — проверено) и мини-шим для клавиатурного фокуса строк.

## Миграция `#ptbl` → Tabulator

| Что сейчас (app.js @ a1c85b3) | Куда в Tabulator |
|---|---|
| Бейджи H/S/G/V/Z, чипы зависимостей, путь с многоточием | `columns[].formatter` — функция возвращает DOM-ноду; существующие `.badge`/`.chip`-стили переиспользуются |
| Кнопки фокуса из `/api/focus/targets`, POST + ✓/✗ (span `.fb`) | formatter кнопок в ячейке «фокус»; после POST — `row.update({...})`/перерисовка ячейки: императивная обратная связь остаётся тривиальной |
| Выбор строки + синк окон (`atlas.selected`, `storage`) | события `rowSelected`/`rowDeselected` → `localStorage`; на `storage`/`focus` — `table.deselectRow()` / `table.selectRow(name)` по данным строки |
| Ширины колонок (`atlas.colw.projects`, `makeResizable`, colgroup) | `resizableColumns` + `persistence` (localStorage); кнопка «сбросить ширины колонок» (set-colreset) переписывается на очистку ключа |
| Фильтр-бокс `#filter` | `table.setFilter(кастом-функция)` по имени/пути/зависимостям |
| Сортировка (клики по th рукодельные) | `headerSort` у колонок + свои `sorter` для агентов/сессий/активности; `initialSort` по активности |
| **Группировка (новое требование)** | `groupBy: row => родительский каталог пути`; проекты в корне — группа «без группы»; `groupHeader: (value, count) => value + ' (' + count + ')'`; сворачивание кликом из коробки, open-state — в persistence |
| Sticky-шапка, скролл-контейнер `.well` | у Tabulator своя структура с шапкой; контейнер и высоту (`height`) оставляем нашими |
| Тысячи строк | virtual DOM включён по умолчанию — ре-рендер `tb.innerHTML = ''` больше не нужен |

Остаётся рукодельным: архив-подвал «выброшенные (N)» с ⬆ (другой жизненный цикл, не строки грида — держим снаружи); `#stbl` (4 колонки) пока не трогаем, второй заход тем же паттерном; логика POST `/api/focus` и журнал статуса.

Риски: тема — в dist-css нет переменных, перебиваем классы `.tabulator-*` значениями из `--palette-*`, bevel/Win95 руками, hover/selected-классы на `--palette-selection`; клавиатура — строки Tabulator не получают `tabindex` сами (сейчас Enter ведёт в первую строку `#ptbl`) — мини-шим на `row.getElement()`; formatter'ы держать stateless (читать только данные строки), иначе гонки при перерисовке; 104 КБ gzip пиним в vendor и обновляем осознанно.

Шаги (одна сессия):
1. Вендорим `static/vendor/tabulator.min.js` + `tabulator.min.css`, подключаем в `index.html` (CSP `'self'` соблюдён).
2. `static/vendor/tabulator-atlas.css`: перебивка `.tabulator-*` под `--palette-*`, радиусы в 0, шрифт inherit.
3. Новый `renderProjects`: `new Tabulator('#ptbl', …)` — 8 колонок с formatter'ами на текущем payload `/api/projects`.
4. События: выбор + `atlas.selected` + `storage`-синк; фокус-кнопки → POST → `row.update()` ✓/✗.
5. `#filter` → `setFilter`; сортеры; `initialSort`.
6. Группировка: `groupBy` по родительскому каталогу пути, `groupHeader` со счётчиком, бакет «без группы».
7. Persistence ширин; переписать set-colreset; удалить DOM-конструктор строк, `makeResizable`, colw-хендлеры (~120–160 LOC наших); смоук: группы, resize, синк окон, фокус-фидбек, объём.

## Почему не остальные

- **AG Grid Community** — уникальный убийца: сама группировка строк — Enterprise-модуль (официальная докa «Row Grouping» импортирует `RowGroupingModule` из `ag-grid-enterprise`). 388 КБ gzip на 8 колонок без ключевой фичи — минус смысла.
- **Grid.js** — лёгкий и приятный, но нет ни группировки (issue #453 висит с 2021), ни виртуализации, ни resize колонок; релизов нет с 2024-03. Для растущих требований — тупик.
- **DataTables** — жив (2026-10), но ядро jQuery, группировка только плагином RowsGroup без сворачивания, resize нет; тащить jQuery-стек ради таблицы в 2026 — шаг назад.
- **TanStack Table** — headless: модель сортировки/группировки хороша, но DOM и весь класс DOM-багов остаются нашими — лечим не то. Плюс v9 перестал поставляться единым файлом (только unminified ESM-дерево) — без билд-степа не вендорится. План Б, если Tabulator разочарует.
- **Оставить ручной стол** — 0 КБ и полный контроль, но группировка ≈150–250 LOC (разбиение, заголовки с colspan, toggle-состояние, стыковка с сортировкой и фильтром, счётчики), и каждая следующая хотелка — снова новый код с тем же классом багов (свежий пример — span в `<tr>`). С библиотекой наш код примерно паритетен (−120–160 старых строк, +~200 клея), но крест «группировка + сортировка + фильтр + resize + виртуализация» уже отлажен и обкатан чужими багрепортами.
