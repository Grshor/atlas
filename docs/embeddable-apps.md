# Какие приложения вообще можно встраивать в atlas (таксономия + вердикт)

Вопрос: «подумай, какие приложения мы вообще можем встраивать (в том стиле, в каком
я предложил встроить wezterm)?» Дата: 2026-10-08. Метод: только read-only проверки
на живой машине — `pacman -Q`, `ss -tlnp`, `systemctl --user list-units`, `curl` на
локальные порты, `herdr api schema --json` (protocol 22). Изменений в коде нет.
Предыстория и запрет на нативное встраивание — `docs/term-embed.md`.

## Вердикт

Встраивание «в стиле wezterm» (чужие пиксели внутри окна atlas) остаётся закрытым
для всех нативных приложений — это ограничение Wayland, а не отсутствующая
фича atlas. Но вопрос
шире, и по нему ответ такой: **встраивать можно только то, что само говорит
HTTP — а на этой машине уже девять локальных HTTP-портов (восемь сервисов),
половина — собственные**.
Топ-3 следующих шага: (1) нативная панель-пульт herdr поверх существующего
импорта snapshot (M), (2) панель оркестратора на `/api/orch` (M, план уже в
term-embed.md), (3) универсальная iframe-панель с allowlist, первый кандидат —
emigate `/daily` (S). XEmbed и VNC-мост — в могилу: первому нечего хостить,
второй не нужен ни одному сервису, который есть сегодня.

## Таксономия

### A. Приложения, говорящие по HTTP/Web — встраиваются напрямую (iframe/webview)

Единственный класс, где «встраивание» реально работает: локальный веб-UI живёт в
`<iframe>`/втором webview внутри панели atlas. Что **фактически** установлено и
слушает порты (`ss -tlnp` + `curl`, 2026-10-08):

| Сервис | Порт | Что показал curl | Что покажет atlas | Размер | Ценность |
|---|---|---|---|---|---|
| emigate (`~/Projects/finance/emigate`) | 3000 UI + 8082 API | `<title>Дневной - emigate</title>`, echarts, `lang="ru"`; **заголовков X-Frame-Options/CSP нет** | дневник/графики сделок внутри панели | S | высокая — свой сервис, идеально ложится |
| Frappe/ERPNext (docker, `frappe_docker-frontend-1 0.0.0.0:8081->8080`) | 8081 | `X-Frame-Options: SAMEORIGIN` (nginx/1.22.1) | ERP-интерфейс — но только через same-origin прокси-роут в axum atlas | S-M | средняя |
| llama-server (decider-4b) | 8095 | встроенный webui llama.cpp (curl без gzip получает `415` — отдаёт UI-ассеты) | чат с локальной моделью для отладки | S | низкая |
| fleet (`~/.local/share/fleet/fleet.py`) | 42983 | `401 unauthorized`; сам описан как «loopback-only web server … launches the UI as a chromeless browser window» | менеджер VPS — нужен токен | S-M | средняя |
| omabudget RUB bridge | 8405 | публичный JSON курсов (`{"amount": 1, "base": "RUB", …}`) | это не UI, а данные: готовый виджет на доску | S | средняя |
| zen-tabs plan/ctl | 8093/8096 | 8093 — directory listing, 8096 — `{"error": "только /status"}` | не UI; статус расширения — в нативную панель (класс B) | — | низкая |

Не установлены (проверено `pacman -Q`): code-server, ttyd, gotty, filebrowser,
jupyter, syncthing, glances. Если когда-нибудь захочется «веб-файлы» или
«веб-терминал» — ttyd/filebrowser ставятся одной командой и встраиваются как
класс A; но это ровно тот случай, где сначала стоит спросить «зачем».

Общая оговорка: у каждого кандидата надо проверять frame-заголовки (выше уже
проверено); сервисы со `SAMEORIGIN` (Frappe) решаются маленьким
reverse-proxy-роутом в axum — atlas проксирует `127.0.0.1:8081` на свой origin.

### B. Приложения с локальным IPC/JSON-API — нативная панель atlas, не веб

- **omp** — `/api/orch` работает (`POST`, SSE: `text|tool|thinking|done`); панель
  оркестратора — план из term-embed.md, здесь не повторяюсь. Размер M.
- **herdr 0.9.3** — публичный socket-API управляющий, и это скорее подарок, чем
  ограничение. В schema (protocol 22) — **102 варианта request**; управляющих
  методов десятки: `pane.list/get/read/focus/send_text/send_keys`,
  `agent.list/get/prompt/wait/focus`, `layout.apply`, `events.subscribe`.
  Панель-пульт **без эмуляции терминала**: дерево workspace/pane, кнопки фокуса
  (`pane.focus`), статус агентов (`agent.list`+`events.subscribe`), хвост вывода
  выбранной панели текстом (`pane.read`), отправка ответа агенту
  (`pane.send_text`). Это полезно: 80% оркестраторского сценария («вижу агентов,
  жду, подглядываю вывод, отвечаю») при ~20% стоимости терминала. Что НЕ получится
  без эмуляции: TUI-рендер (omp-вывод, vifm, btop внутри панели) — `pane.read`
  даёт текстовый слепок, не экран. Писать xterm.js-фронтенд = «свой терминал»,
  который уже был отклонён, — не делаем. Размер: S (дерево+фокус, данные snapshot
  уже импортируются в atlas) → M (агенты, хвосты, send).
- **git** — репозитории atlas уже импортирует; встраивать нечего.
- **Zen (zen-browser-bin 1.22.2b-1)** — удалённого HTTP-API нет: в `ss` ни
  marionette (2828), ни remote-debugging (6000) не слушается; это firefox-ветка,
  CDP не поддерживает. Канал уже существует и он другой: web-расширение
  «Разбор вкладок» + локальные сервисы (`zen-tabs-ctl.service` — «Пульт локальных
  моделей для расширения», порт 8096). atlas может показать статус этого канала
  нативно (S), но «встроить браузер» — нельзя и не нужно: вкладки браузера —
  не панель контрольного центра.
- **Obsidian 1.13.7-2** — API нет; vault — просто файлы, и atlas их уже
  индексирует (380 `vault_note` в поиске). Нечего встраивать — интеграция уже
  состоялась на уровне данных.
- **jobwatch** — HTTP-порта нет вовсе (фид → TG); нативная панель означала бы
  чтение его внутреннего стора — L, ценность сомнительная. Убить идею.

### C. X11-встраивание (XEmbed/GtkSocket) через XWayland — не применимо

atlas — GTK3 (term-embed.md), то есть GtkSocket формально доступен. Но хостить
нечего: XEmbed-сторону сегодня реализуют почти исключительно старые GTK3-приложения
(панельные апплеты), а реальный набор пользователя — wezterm, herdr, Zen
(Gecko), Obsidian (Electron), vesktop — не умеет ни GtkPlug, ни XEmbed. Протокол
мертвый, кандидатов ноль. Похоронить.

### D. Скрин-скрейпинг-мост: headless-композитор + wayvnc + noVNC в iframe

Единственный универсальный способ «любое приложение внутри atlas»: вложенный
композитор (cage), VNC-сервер, noVNC-клиент в iframe. Честная цена: лишний
композитор и второй графический стек на каждое приложение, латентность ввода,
хрупкость (ресайзы, фокус, буфер обмена через тройной перехват), поддержка
своими руками. Оправдан только если какое-то приложение без API станет
критичным для панели. Сегодня такого приложения нет — не строить.

### E. Единство на уровне WM (не встраивание) — уже работает

Hyprland-группы (`tools/orch-group.sh`, term-embed.md «Путь Б») — правильный
ответ везде, где приложение обязано остаться настоящим приложением: терминалы
(wezterm+herdr), Zen, Obsidian, btop. Специальные воркспейсы — та же семья.
Когда пользователь хочет «цельное окно» из настоящих окон — это и есть ответ,
кода в atlas не требуется.

## Что НЕ встраивается и почему (перестаём надеяться)

wezterm, herdr и вообще любое нативное Wayland-приложение не может жить внутри
окна atlas: в Wayland нет протокола «reparent чужого toplevel в моё окно» — ни
в core (xdg_shell), ни в wayland-protocols, ни в наборе Hyprland; единственная
лазейка (XEmbed через XWayland) требует поддержки со стороны встраиваемого
приложения, которой нет. Это констатация уровня протокола, а не версия/настройка —
подробно, с цитатами из `wezterm start --help` и `hyprland-protocols`, см.
`docs/term-embed.md`, путь А. Единственный класс исключений — приложения,
которые сами рисуют в браузере (класс A выше): их «встраивание» — это iframe,
а не чудо Wayland.

## Рекомендация: топ-3 следующих шага

1. **Пульт herdr — нативная панель (M).** Механизм: обычная панель atlas над
   уже импортируемым `herdr api snapshot` + методы `pane.focus`, `agent.*`,
   `pane.read`, `pane.send_text`, `events.subscribe`. Первый шаг: отрисовать
   snapshot деревом с кнопками фокуса — это чисто фронтенд на S (данных достаточно).
2. **Панель оркестратора на `/api/orch` (M, эхо-версия S-M).** Механизм
   нативный; первый шаг — эхо-панель (ввод + рендер `text|tool|thinking|done`),
   план и дыры — term-embed.md «Путь В».
3. **Универсальная iframe-панель с allowlist (S).** Один generic-панель-тип
   «встроенный URL» (allowlist в настройках, sandbox-атрибуты), первый жилец —
   emigate `/daily` (frame-заголовков нет — проверено). Второй кандидат —
   Frappe через маленький same-origin прокси-роут в axum.

**Убить и не вспоминать:** xterm.js-«свой терминал» в atlas (отклонён; пульт herdr
закрывает сценарий дешевле); XEmbed-хостинг (нечего хостить); VNC-мост (нет
приложения без API, которое того требует); «встроить Zen/Obsidian» (нет API,
интеграция уже существует на уровне данных/расширения); ttyd+btop в iframe
(btop и так живёт соседней вкладкой в группе — ценности не добавляет).
