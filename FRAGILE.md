# Хрупкие места atlas — отчёт для ревью

Дата: 09.10.2026 · HEAD: `c8b7efc` · Rust ~17.5k строк + фронт ~6.7k (app.js 5416,
app.css 1257), тестов 131. Всё, что ниже, — не гипотезы: каждый пункт — либо
инцидент последних двух недель, либо задокументированное ограничение в коде.

Критерий отбора — три класса хрупкости:

- **A. Переизобретение готового.** Мы вручную делаем то, для чего есть
  выстраданные решения: эмулятор терминала, супервизор процессов, rpc-клиент,
  песочница. Своё мы делаем «довольно плохо» (цитата владельца) — не потому что
  плохо пишем, а потому что у готового решения десятилетия гречихи.
- **B. Контракт «на тексте».** Модули ссылаются друг на друга через имена
  файлов, строки-шаблоны и паттерны, а не через идентификаторы/структуры.
  Переименование или совпадение формы молча ломает связь.
- **C. Состояние в процессе.** Рабочие задания, PTY, кольца вывода и их
  наблюдатели живут в памяти сервера; смерть процесса теряет работу и врёт в БД,
  пока её не приберёт `reap_stale`.

Приоритеты: **P0** — чинить сейчас (реальные инциденты), **P1** — следующий
круг, **P2** — по необходимости. Оценки цены: S ≤ день, M — несколько дней,
L — неделя+.

## 1. Терминал: свой эмулятор внутри webview (P0, L)

`term.rs` (735 строк) держит PTY-реестр (`proj-<имя>`, `herdr`), WS-мост и
ленивый спавн; `static/app.js` рисует это xterm.js внутри WebKitGTK. Это
фактически **свой терминальный эмулятор**, и он системно отстаёт от настоящих:

- модификаторы клавиш (Shift+Enter) — xterm.js сам kitty-keyboard не умеет;
  в `static/js/terminal.js` есть слой kitty-уровня 1: приложение включает
  протокол (`CSI > flags u`) — функциональные клавиши с модификаторами
  кодируются CSI u (Shift+Enter = `CSI 13;2u`); без протокола CLI видят
  обычный Enter (это и есть legacy-поведение настоящих терминалов);
- буфер обмена: картинки из клипборда webview отдаёт неохотно (сделали костыль
  с `/api/clipboard/image` и вставкой пути);
- жалобы владельца: открытие herdr-сессии, создание вкладок «и прочее».

**Чем заменить.** Терминал должен жить в терминале: wezterm (`wezterm cli
spawn`, `wezterm cli send-text`, вкладки/окна через CLI) — в перспективе OSS —
терминал, который выбрал пользователь. Панель atlas остаётся **пультом**:
список сессий, статус, кнопки «открыть/фокус», хвост вывода для наблюдения —
но не рендерит сам терминал. herdr остаётся менеджером сессий, мы перестаём
владеть PTY. Это одновременно убирает класс C для терминала: сессии живут в
wezterm и переживают рестарт atlas.

Этапность: (1) herdr-клиент и проектные оболочки открывать в wezterm, панель
показывает реестр + «открыть»; (2) WS-мост и xterm.js выпиливаются; (3) при
подготовке к OSS — абстракция «терминальный бэкенд» (wezterm | пользовательский
эмулятор).

## 2. Ворктри-слаг как контракт на тексте (P0, S)

Делегация создаёт `~/.atlas-wt/<проект>-<id>-<4hex>`, а импортёры **парсят этот
шаблон обратно** (`delegation_parent` в `importers.rs`), чтобы отличить ворктри
от проекта. Это уже однажды выстрелило: omp-сессия ворктри резолвилась в каталог
и создала фантомный проект. Чинили компонентным тестом `$HOME/.atlas-wt`, но
шаблон имени остался контрактом: каталог `lamplife-1234-abcd` рядом с
`~/.atlas-wt` или совпадение форм продолжат обманывать эвристику.

**Заменить.** Внутрь ворктри класть маркер `.atlas-deleg.json`
(`{"item":id,"project":"…","branch":"…"}`), импортёры спрашивают файл, а не
парсят имя. Обратная совместимость: старые ворктри без маркера считать по
шаблону ещё один релиз. Цена S, выкидывает целый класс совпадений.

## 3. Связи по именам проектов (P0, M)

`sessions.project`, `delegation.project`, источники, фокус — везде **строка
имени** (часто ещё и norm-ed сравнение). Переименование проекта — а это
обычная операция — молча оставляет сессии/делегации на старом имени: история
отклеивается, `latest_session_file` перестаёт находить сессии (наш свежий
механизм погружения делегаций тоже на имени), диф ревью смотрит не туда.

**Заменить.** `project_id` INTEGER внешним ключом в `sessions`, `items`,
источниках; имя остаётся отображением. Миграция одноразовая иguarded, дальше
переименования безопасны по определению.

## 4. Фронт: 5416 строк ручного SPA (P0, M–L)

`static/app.js` — один файл без модулей и каркаса: глобальные функции,
самописные модалки, ручной scroll-анкоринг, ручные тикеры (`delegLogPoll`,
`delegEnsureTick`), самописная синхронизация окон через localStorage. Почти
каждый фронтовый инцидент этого месяца — отсюда: пустая выбранная строка
(маркер `::before` не влез в 25px ячейку), прыжки скролла при ререндере,
«к ревью» без хода воркера (починено добавлением секции), оптимистичные чипы.

**Минимальный системный шаг** (без npm в рантайме, что является ограничением
проекта): нарезать `app.js` на ES-модули по панелям, вынести модалки/тикеры в
маленькие хелперы с тестами, ввести правило «DOM-ререндер обязан сохранять
анкор». **Следующий шаг**: собирать фронт Vite'ом на этапе сборки (npm остаётся
build-time зависимостью, в рантайме по-прежнему статика из бинаря) и взять
Preact/lit для панелей с состоянием. Это самое дорогое по времени из P0, но
именно здесь случается большинство видимых багов.

## 5. Делегация/rpc: два ручных драйвера + ручной супервизор (P1, M)

Сейчас omp-протокол говорят два самописных клиента: `orch.rs` (панель,
approvals-механика, авто-денай 5 мин) и `delegate.rs` (headless: свои потоки,
свой watchdog, своё зеркалирование кадров в кольцо). Плюс `runner.rs` — свой
супервизор процессов с кольцами и kill-grace. Инциденты этого класса: always-ask
на всё, тихий авто-денай, ронявший ходы, 16 залипших `xdg-open`, осиротевшие
дети при рестарте сервера.

**Заменить.** (а) Один библиотечный слой `omp_rpc` (подключение, кадры,
mirroring), оба потребителя — риск расползания семантики падает вдвое;
(б) воркеров запускать через `systemd-run --user` transient-юниты: переживают
рестарт atlas, честный статус из systemctl, логи в journal; (в) авто-денай —
настраиваемый и видимый в панели (сейчас карточка просто исчезает).

## 6. Golden-пробы против реального omp (P1, S–M)

Тесты `orch.rs` содержат **модель** матчера `bash.patterns` и оверлея. За два
дня она дважды разошлась с реальностью (массивы заменяются, а не сливаются;
сегменты парсятся и на `;`; критичный override под yolo игнорируется). Ручные
rpc-пробы это ловят, но они не автоматизированы.

**Заменить.** `#[ignore]`-тест, который спавнит реальный `omp --mode rpc` на
временной сессии и сверяет 6–8 канонических команд с фактическим решением
(карточка/блок/свободно) — тот самый прогон, что мы делали руками из
`/tmp/atlas-appr-probe-run`. Запускать в CI/по кнопке; дрейф семантики станет
красным тестом, а не сюрпризом.

## 7. Одобрения-паттерны: политика, не изоляция (P1, M)

`bash.patterns` — текстовый фильтр: он уже блокировал безобидный `git commit`
(в сообщении упоминался инструмент из гварда), а в ветке без разбора на
сегменты `prompt` мёртв под yolo. Это осознанный компромисс, но его предел
известен:Patterns — грубый фильтр; изоляцию даёт только окружение.

**Системно.** Воркеров делегации (не интерактивного оркестратора) запускать в
sandbox: `systemd-run --user -p PrivateTmp=yes -p ProtectHome=read-only …` или
bubblewrap с записью только в worktree. Паттерны остаются как первый рубеж.
Для интерактивной панели ничего не менять — там карточки работают.

## 8–13. Остальное кратко

- **http.rs 5962 строки** — роуты всех доменов + тесты в одном файле; разрез на
  `board.rs`/`delegate_routes.rs`/`open.rs`/`terminal.rs`/`clipboard.rs` дёшев
  и сразу снижает цену правок (P1).
- **embed.rs brute-force cosine** — при десятках тысяч документов станет
  заметен; sqlite-vec вернём по необходимости (P2, осознанно отложено).
- **stt.rs** — ручной рекордер+распознавание, не обкатан на чужом железе
  (P2, аудит).
- **main.rs DMABUF-обходка** — env-переменная, протухнет молча при обновлении
  webkit; проверять версию при старте и предупреждать (P2, S).
- **`pkill -x atlas`** убивает GUI и сервис разом (одно имя); либо отдельное
  имя серверу, либо README-предупреждение остаётся (P2, S).

## Рекомендованный порядок

1. **Сейчас (S):** маркер-файл ворктри (§2) — закрывает целый класс фантомов.
2. **Ближайший спринт:** `project_id` (§3) — миграция, после которой
   переименования безопасны; разрез `http.rs` (§8) по ходу обычных правок.
3. **Терминал (§1)** этапом 1: herdr/проектные оболочки — в wezterm, панель —
   пульт. Это снимает текущую боль и готовит OSS-шаг «терминал пользователя».
4. **Параллельно малой кровью:** golden-пробы omp (§6), `omp_rpc`-слой (§5а),
   sandbox воркеров (§7).
5. **Фронт (§4)** — самым большим куском, когда будет согласован каркас
   (build-time npm допустим? — вопрос к владельцу).
